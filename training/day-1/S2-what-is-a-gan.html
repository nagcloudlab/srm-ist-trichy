🎲 What Is “Random Noise”?

Just a vector of random numbers. No meaning. No pattern.

noise = torch.randn(1, 5)
[-0.42, 1.31, -0.87, 0.15, 2.01]

Like rolling 5 dice. That’s it.

How many random numbers?

  • Simple GAN: 1 to 64
  • Image GAN: 100 (typical)
  • More numbers = more variety

🔄 How It Works — The Full Data Flow

1. G takes noise, creates fake

2. D sees real + fake images

3. D says “real or fake?”

4. Both learn from the verdict

🔁 The Training Loop — Two Steps, Repeated

Step A — Train D

  • Real image → D should say 1
  • Fake image → D should say 0
  • Update D’s weights only

D is a binary classifier. G is frozen.

then

Step B — Train G

  • G creates a fake from noise
  • D judges the fake
  • G wants D to say 1 (fooled!)
  • Update G’s weights only

G never sees real images. D is frozen.

Repeat Step A + Step B thousands of times → both improve → fakes get realistic

Why This Works — Opposite Goals

D wants…G wants…
Real imagesD(real) = 1(doesn’t care)
Fake imagesD(fake) = 0D(fake) = 1

They disagree on fake images. This tension drives all learning.

End goal: G gets so good that D outputs 0.5 for everything — “I have no idea if this is real or fake.”

🧬 What Does G Actually Learn?

G never sees real images. It only hears “good” or “bad” from D. Over time, G picks up patterns:

  • White strokes on dark background
  • Smooth curves and straight edges
  • Consistent stroke thickness
  • Centered in frame

G creates new images that never existed before.

Not copying

G does NOT memorize training images. It learns the statistical patterns and synthesizes new examples that match those patterns.

Why this matters

GANs generate brand new data. New faces, new molecules, new medical scans, new training samples for other models.

📉 The Loss Function — BCE

Both networks use Binary Cross-Entropy — the same loss from classification.

BCE(p, y) = −[y · log(p) + (1−y) · log(1−p)]
SymbolMeaning
pD’s prediction (0 to 1)
yTarget label (1 = real, 0 = fake)
logNatural logarithm

When y = 1 (real image)

BCE = −log(p)

Pushes p toward 1

When y = 0 (fake image)

BCE = −log(1−p)

Pushes p toward 0

📊 BCE Loss — Visualized

When target = 1 (real image)

p near 1 → tiny loss  |  p near 0 → ∞

When target = 0 (fake image)

p near 0 → tiny loss  |  p near 1 → ∞

BCE harshly punishes confident wrong answers — that’s what drives fast learning.

Discriminator Loss vs Generator Loss

D Loss

LD = −[log D(x) + log(1 − D(G(z)))]

D(x) → should be 1 (real)

D(G(z)) → should be 0 (fake)

d_loss = BCE(D(real), 1) + BCE(D(fake), 0)

G Loss

LG = −log D(G(z))

G wants D(G(z)) → 1

Loss is low when D is fooled

g_loss = BCE(D(fake), 1)

The Full GAN Objective — Min-Max Game

minG maxD   E[log D(x)] + E[log(1 − D(G(z)))]

D wants to maximize

  • D(x) close to 1
  • D(G(z)) close to 0
  • Both log terms → high

G wants to minimize

  • D(G(z)) close to 1
  • Fool D so the expression drops
  • Only controls second term

They play this game until balance — the Nash equilibrium.

The Key Trick: .detach()

Training D — with .detach()

fake = generator(noise).detach()

Gradient stops at fake — only D learns.

We need G to produce fakes, but D is the student right now. G just provides the output and sits still.

Training G — no .detach()

fake = generator(noise)

Gradients flow back through D into G — G learns from D’s feedback.

Now G is the student. D’s judgment becomes the teaching signal for G.

.detach() = “use this value but stop gradients from flowing through it”

Controls who learns when. The simplest yet most important trick in GAN training.

The Full Training Step in Code

Step A: Train Discriminator

real_pred = D(real_images)
fake_imgs = G(noise).detach()
fake_pred = D(fake_imgs)
d_loss = BCE(real_pred, 1) + BCE(fake_pred, 0)
d_loss.backward()
d_optimizer.step()

Step B: Train Generator

fake_imgs = G(noise)
fake_pred = D(fake_imgs)
g_loss = BCE(fake_pred, 1)
g_loss.backward()
g_optimizer.step()

That’s the complete GAN training loop. Everything else in this course builds on this.

⚖️ The Balance Problem

Superior Discriminator

D is too confident. Gradient = flat.

G has no way to improve!

Why this happens

  • D trains faster than G (classifying is easier than creating)
  • D becomes perfect → all fakes score 0
  • BCE gradient at 0 is flat — no direction
  • G receives zero useful feedback

The rule

D and G must stay at similar skill levels

Fixes: label smoothing, lower D learning rate, train D fewer steps. We cover these on Day 2.

🧠 Knowledge Check

G never sees real images. So how can it possibly learn to make realistic ones?

Click to reveal

Through D’s gradient feedback. D has seen real data and learned what “real” looks like. When D says “this fake scored 0.2”, the gradient encodes which direction to adjust G’s weights. G doesn’t need the target directly — it just needs a critic who keeps raising the bar and whose judgment carries a precise gradient signal.

What would break if you removed .detach() from the D training step?

Click to reveal

Gradients would flow through G during D’s training, updating G’s weights at the wrong time with the wrong objective. G would learn to help D (produce easier-to-catch fakes) rather than fool D. Both players end up on the same team — the adversarial game collapses.

If D always outputs 0.5 from the very start (random guessing), would G still learn?

Click to reveal

No. If D can’t distinguish real from fake, its gradient feedback is meaningless noise. G needs a competent critic. That’s why we train D first each step — D must be slightly ahead of G so its feedback points G in a useful direction. A teacher who doesn’t know the subject cannot teach.

GANs use the same BCE loss as a simple classifier. Why does the same loss create new images instead of just labeling them?

Click to reveal

Because of who receives the update. In a classifier, the model adjusts weights to output correct labels for fixed inputs. In a GAN, G’s weights adjust to make D output the wrong label for its generated pixels. The loss is identical, but it’s applied to a network whose outputs are images, not labels. Same engine — completely different car.
