Four Problems with Vanilla Gradient Descent

1. Ravines

Loss surface is steep in one direction, flat in another. Gradient bounces back and forth across the steep walls instead of rolling down the valley.

Zigzag oscillation, slow convergence

2. Saddle Points

Gradient = 0, but it's not a minimum — it's a flat region between hills. The optimizer gets stuck with no signal to move.

Training plateaus for many epochs

3. Noisy Gradients

Mini-batch gradients are estimates. Each batch gives a slightly different direction. The path is jittery instead of smooth.

Noisy updates, unstable training

4. One LR for All

Some parameters need fast updates (rare features), others need slow updates (common features). One learning rate can't serve both.

Under/over-shooting different params

SGD — Stochastic Gradient Descent

w = w − η · ∇Lbatch

Strengths

  • Simple: one line of code
  • Noise helps: escapes shallow local minima
  • Generalizes well: flat minima preferred
  • Low memory: no state to store

Weaknesses

  • Oscillates in ravines (zigzag path)
  • Gets stuck at saddle points
  • Sensitive to learning rate choice
  • Same LR for all parameters

PyTorch

optim.SGD(params, lr=0.01)

SGD + Momentum

v = βv + ∇L   |   w = w − ηv

The Ball Analogy

Imagine a ball rolling down a hill.

  • Gradient = slope at current position
  • Velocity (v) = ball's accumulated speed
  • β = friction (typically 0.9)

The ball builds speed on consistent slopes and damps oscillations across ravines.

Nesterov Accelerated Gradient (NAG)

v = βv + ∇L(w − ηβv)
w = w − ηv

Look-Ahead Trick

STANDARD

Gradient here

vs
NESTEROV

Gradient there

Nesterov computes gradient at the predicted future position, not the current one.

Why It's Better

  • Corrective: if momentum overshoots, look-ahead gradient pulls back
  • Faster convergence on convex problems
  • Mathematically optimal for smooth functions

In Practice

Marginal improvement over standard momentum in deep learning. Often used, rarely the deciding factor.

optim.SGD(params, lr=0.01, momentum=0.9, nesterov=True)

Adagrad — Adaptive Gradients (2011)

G = G + (∇L)²
w = w − η · ∇L / (√G + ε)

How It Adapts

ParameterPast GradientsGEffective LR
Rare featureMostly zeroSmallLarge ↑
Common featureAlways largeLargeSmall ↓

Strengths

  • Per-parameter LR: each weight gets its own rate
  • Great for sparse data: NLP, recommender systems
  • No manual LR tuning per layer

Fatal Flaw

G only grows (sum of squares). The effective learning rate monotonically shrinks and eventually reaches zero.

Training stops prematurely.

optim.Adagrad(params, lr=0.01)

RMSProp — Root Mean Square Propagation (2012)

G = βG + (1−β)(∇L)²
w = w − η · ∇L / (√G + ε)

Adagrad vs RMSProp

AdagradRMSProp
G updateG = G + g²G = βG + (1−β)g²
MemoryAll historyRecent window (~1/1−β)
LR over timeAlways shrinksCan recover

Strengths

  • Fixes Adagrad's dying LR problem
  • Adapts per-parameter (like Adagrad)
  • Works well for non-stationary problems (changing data)

In GANs

The original WGAN paper uses RMSProp (not Adam) because Adam's momentum fights weight clipping.

optim.RMSprop(critic.parameters(), lr=5e-5)

Typical β

β = 0.99 (default). Window ≈ 100 recent gradients.

Adam — Adaptive Moment Estimation (2015)

m = β1m + (1−β1)∇L
v = β2v + (1−β2)(∇L)²
m̂ = m / (1−β1t)
v̂ = v / (1−β2t)
w = w − η · m̂ / (√v̂ + ε)

What Each Part Does

v (2nd moment)Gradient magnitudeRMSProp
m̂, v̂Bias correctionWarm-up fix

Default Parameters

η0.001Learning rate
β10.9Momentum decay

ε10−8Numerical stability

Why Adam Works So Well

Adam = Momentum + RMSProp

  • Momentum (m) smooths direction → no zigzag
  • Adaptive (v) scales per-param → no manual tuning
  • Bias correction → stable from step 1

The Default Choice

Adam works well on 95% of problems with default settings. Start here. Switch only if you have a reason.

optim.Adam(params, lr=1e-3)

Why Lower β1?

In adversarial training, the loss landscape shifts every step (because the other network is also changing). High momentum remembers old directions that are no longer valid.

β1=0 means: "Only trust the current gradient."

PyTorch Snippets

# DCGAN
optim.Adam(params, lr=2e-4, betas=(0.5, 0.999))
# WGAN-GP
optim.Adam(params, lr=1e-4, betas=(0.0, 0.9))

AdamW — Adam with Decoupled Weight Decay

Adam + L2 (Wrong)

∇L' = ∇L + λw

Weight decay is added to gradient before adaptive scaling. Adam's v divides it, weakening the regularization.

AdamW (Correct)

w = w − η(m̂/√v̂) − ηλw

Weight decay applied separately, after the adaptive step. Full regularization strength preserved.

Why It Matters

  • AdamW generalizes better than Adam + L2
  • Default in Transformers, LLMs, ViT
  • Loshchilov & Hutter 2019

PyTorch

optim.AdamW(params, lr=1e-3, weight_decay=0.01)

Default for HuggingFace Transformers, timm, most modern training.

Rule: If you use Adam, switch to AdamW. It's strictly better with regularization.

Learning Rate Scheduling

Step Decay

Reduce LR by factor at fixed epochs

lr = lr × 0.1 every 30 epochs

Cosine Annealing

Smooth cosine curve from high to low

lr = lr_min + ½(lr_max − lr_min)(1 + cos(πt/T))

Warm-Up + Decay

Ramp up LR, then decay. Used in Transformers.

0 → lr_max (linear) → 0 (cosine)

Reduce on Plateau

Watch val loss; reduce if stuck

if no improvement for N epochs: lr ×= 0.1

Modern default: AdamW + Cosine Annealing with Warm-Up (used in GPT, BERT, ViT)

A 7B parameter model (LLaMA-7B):

  • Weights: 28 GB (fp32)
  • Adam state: +56 GB
  • Total: 84 GB just for optimizer

Solutions

  • 8-bit Adam: quantize state to int8 (bitsandbytes)
  • Adafactor: factorized 2nd moment (less memory)
  • FSDP: shard state across GPUs
  • SGD: no state at all (sometimes worth it)

Common Optimizer Mistakes

1. Forgetting zero_grad()

Gradients accumulate by default. Without zeroing, each step adds to previous gradients.

optimizer.zero_grad() # BEFORE backward()

2. Wrong LR for Adam

Adam's default is 1e-3. Using SGD's typical 0.1 with Adam causes divergence.

Safe range: 1e-4 to 3e-3

3. Not registering all params

Forgetting to pass all model parameters means some weights never update.

optim.Adam(model.parameters()) # ALL params

4. Adam for GAN without tuning

Default β1=0.9 causes instability in adversarial training. Use 0.5 (DCGAN) or 0.0 (WGAN-GP).

Summary

Start with Adam

Default lr=1e-3 works 95% of the time. Switch to AdamW if using weight decay.

Momentum Smooths

Past gradients build velocity. Prevents zigzag. β=0.9 is standard.

Adaptive = Per-Param

RMSProp and Adam scale each weight's LR based on its gradient history.

GANs Need Tuning

Lower β1 (0.5 or 0), lower LR (2e-4), RMSProp for WGAN.

Knowledge Check

Q1: SGD oscillates in a ravine. You add momentum with β=0.9. Why does this help?

Click to reveal

Momentum accumulates velocity. The across-ravine oscillations cancel out (alternating +/-), while the along-ravine component reinforces (same direction). Result: the ball rolls down the valley instead of bouncing wall to wall.

Q2: Why does WGAN use RMSProp instead of Adam?

Click to reveal

WGAN uses weight clipping (clamping weights to [-c, c]). Adam's momentum term fights the clipping — it builds velocity that pushes weights beyond the clip range, then they get clamped back, wasting the update. RMSProp has no momentum, so it doesn't fight clipping.

Q3: Your Adam training diverges. The learning rate is 0.01. What's likely wrong?

Click to reveal

LR is too high for Adam. Adam's default is 1e-3 (0.001). Using 0.01 (10x higher) often causes divergence because Adam already adapts the effective LR internally. Try 1e-3 or lower. For GANs, use 2e-4.

Q4: Adam uses 2× more memory than SGD+Momentum. Why?

Click to reveal

Adam stores two running averages per parameter: m (first moment / gradient direction) and v (second moment / gradient magnitude squared). SGD+Momentum only stores one (velocity). Each is the same size as the parameter tensor, so Adam uses 2× the state memory.

Q5: Why does WGAN-GP use β1=0 (no momentum at all)?

Click to reveal

In adversarial training, the loss landscape shifts every step because both networks are changing simultaneously. Momentum from step t-10 points in a direction that may be completely wrong at step t. Setting β1=0 means "only trust the current gradient" — each update reflects the current adversarial state, not a stale average.
