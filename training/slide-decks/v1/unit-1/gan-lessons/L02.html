Lesson 02

Build Your First GAN

A Generator that learns to produce the number 7 — without ever being told the answer

The Task

Recall from S2: G creates fakes, D judges real vs fake, both improve through competition.

ComponentOur Setup
Real dataThe number 7.0
GeneratorTakes noise → tries to output 7.0
DiscriminatorSees a number → says "real" (1) or "fake" (0)

The Twist

G never sees the number 7. It only gets feedback from D.

“Can the Generator learn to produce 7.0 without ever being told the answer is 7?”

Yes. That's what we're about to build.

Build the Generator

h = ReLU(W₁ · noise + b₁)   →   out = W₂ · h + b₂

PyTorch Code

generator = nn.Sequential(
    nn.Linear(1, 16),   # noise → 16
    nn.ReLU(),
    nn.Linear(16, 1),   # 16 → 1 output
)

Before training: noise 0.337 → output -0.054 (random garbage)

Build the Discriminator

PyTorch Code

discriminator = nn.Sequential(
    nn.Linear(1, 16),   # input → 16
    nn.ReLU(),
    nn.Linear(16, 1),   # 16 → 1
    nn.Sigmoid(),        # squash to 0-1
)

D outputs a probability:

OutputMeaning
1.0"Definitely real"
0.5"No idea"
0.0"Definitely fake"

Before training: D(7.0) ≈ 0.51 — clueless!

The Sigmoid Curve

σ(x) = 1 / (1 + e−x)
Input xσ(x)D says
+5≈ 0.993"real"
0= 0.500"no idea"
−5≈ 0.007"fake"

Sigmoid guarantees output is always between 0 and 1 — a valid probability.

BCE Loss — With Numbers

BCE(p, y) = −[y · log(p) + (1 − y) · log(1 − p)]

D says 0.9 for real (y=1)

BCE = -[1 × log(0.9)]
    = -(-0.105)
    = 0.105

Correct → small penalty

D says 0.9 for fake (y=0)

BCE = -[log(1 - 0.9)]
    = -log(0.1)
    = 2.303

Wrong → huge penalty

How the Two Losses Work

LossWho learnsGoal
LD = −log D(7) − log(1−D(G(z)))DiscriminatorSay 1 for real, 0 for fake
LG = −log D(G(z))GeneratorMake D say 1 for fake (non-saturating form; minimax G would minimize log(1−D(G(z))))

Training Loop — Step A: Train D

1. Show D real data → should say 1

real_data = torch.tensor([[7.0]])
real_pred = discriminator(real_data)
loss_real = loss_fn(real_pred, real_label)

2. Show D fake data → should say 0

noise = torch.randn(1, 1)
fake = generator(noise).detach()
fake_pred = discriminator(fake)
loss_fake = loss_fn(fake_pred, fake_label)

3. Update D only

dis_loss = loss_real + loss_fake
dis_optimizer.zero_grad()
dis_loss.backward()
dis_optimizer.step()

Training Loop — Step B: Train G

1. Generate fake data (no detach!)

noise = torch.randn(1, 1)
fake = generator(noise)     # NO detach
fake_pred = discriminator(fake)

2. G wants D to say "real"!

gen_loss = loss_fn(fake_pred, real_label)
# G's goal: fool D into saying 1

3. Update G only

gen_optimizer.zero_grad()
gen_loss.backward()
gen_optimizer.step()

Why .detach()?

Without .detach()

D's backward pass sends gradients through G too.

Result: G's .grad fills with gradients of D's loss. Only dis_optimizer steps, and gen_optimizer.zero_grad() clears them before Step B — so G isn't corrupted here, but it's wasted compute and stale grads would leak if zero_grad moved.

fake = generator(noise)
# Gradient: D ← fake ← G  (G gets stray grads)

With .detach()

"Use this value, but don't send gradients back to G."

Result: Backprop stops at fake. Step A touches only D. Clean and cheap.

fake = generator(noise).detach()
# Gradient: D ← fake  (stops here!)

Step A: D learns, G is frozen  (.detach)

Step B: G learns, D is frozen  (only gen_optimizer runs)

They take turns. That's what makes it adversarial.

Full Architecture

What Scales Up?

Stays the same (forever)

  • Step A / Step B alternating
  • .detach() in Step A
  • BCE loss
  • Two separate optimizers
  • G never sees real data

Changes as we scale

  • Data: 1 number → 784 pixels
  • Networks: 16 hidden → 256, 512
  • Noise: 1 → 64 (more variety)
  • G output: none → Tanh
  • D hidden: ReLU → LeakyReLU
“Same recipe. Bigger ingredients. That's Lesson 03.”

Knowledge Check

What breaks if you remove .detach() from Step A?

Click to reveal

Less than you might think! D's backward pass also flows into G and fills G's .grad with gradients of D's loss — but only dis_optimizer.step() runs, and gen_optimizer.zero_grad() clears those stray grads before Step B. So in this code order G is not corrupted. Why detach anyway: Step A should only be D's step, it avoids wasted backprop through G, and if zero_grad were moved or forgotten the stale gradients would leak into G's update.

If the GAN perfectly converges, what should D output for everything?

Click to reveal

0.5 for both real and fake. When G is perfect, D can't tell real from fake anymore. It outputs 0.5 ("no idea") for everything. That's the Nash equilibrium — neither player can improve.

G uses real_label in its loss. Isn't that lying? Why does it work?

Click to reveal

It's not lying — it's G's objective. G wants D to say 1 for its fakes. By computing loss against real_label=1, G gets penalized whenever D isn't fooled. Higher penalty → bigger gradient → G adjusts more → better fakes next round.
