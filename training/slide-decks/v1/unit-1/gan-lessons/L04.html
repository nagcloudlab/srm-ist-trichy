Recall: Linear Layers Lose Spatial Structure

From L03: Linear flattens the image — all spatial structure is destroyed. Convolutions fix this by looking at neighbors.

Linear: Pixel Soup

[p1, p2, p3, ... p784]

No rows, no columns, no neighbors. That's why L03 images were blurry.

Conv: Sees Neighbors

A small filter slides across the 2D image, looking at local patches.

Edges, curves, and shapes are preserved.

What Is a Convolution?

A small filter (3×3) slides across the image, looking at patches of nearby pixels.

Padding — Keep the Same Size

Without Padding

5×5 image + 3×3 filter = 3×3 output
Image shrinks every layer!

With Padding = 1

Add a ring of zeros around the image.
5×5 image + 3×3 filter = 5×5 output
Same size!

output = input - kernel + 2 × padding + 1

Example

5 - 3 + 2×1 + 1 = 5

Padding = 1 keeps output the same as input.

“In a neural network, filter values are learned — the network figures out which patterns are useful on its own!”

Multiple Filters = Feature Maps

nn.Conv2d(in_channels=1, out_channels=16, kernel_size=3, padding=1)

This creates 16 different 3×3 filters. Each one slides across the entire image.

  • Filter 1 might detect: vertical edges
  • Filter 2 might detect: horizontal edges
  • Filter 3 might detect: corners
  • Filter 16 might detect: diagonal lines

Shape Trace

Output: [batch, 16, 28, 28]

Same height and width (padding=1).
But now 16 feature maps — each detected a different pattern.

Stride = 2 — Shrinking the Image

stride=1

Filter moves 1 pixel at a time → same size output

stride=2

Filter jumps 2 pixels → half size output
28×28 → 14×14

output = (input - kernel + 2×padding) / stride + 1

(28 - 4 + 2×1) / 2 + 1 = 14

ConvTranspose2d — Growing the Image

Generator's challenge: Go from noise (small) to a full image (big).

How It Works

Each input value gets spread into a larger area using the filter. Where results overlap, they add together.

output = (input - 1) × stride - 2 × padding + kernel

(7 - 1) × 2 - 2 × 1 + 4 = 14

Multiple Layers — Feature Hierarchy

Batch Normalization

The Problem

Values can explode or vanish through layers:

Layer 1: [0.5, 0.8, 0.3]
Layer 2: [5.2, 8.1, 3.7]
Layer 3: [52, 81, 37] ← exploding!

The Fix

BatchNorm recenters to mean=0, scale=1:

[52, 81, 37, 69] → [-0.46, 1.27, -1.36, 0.55]

x̂ = (x - μ) / σ

Analogy

Without BatchNorm:
Student 1: 95/100 • Student 2: 950/1000
Hard to compare — different scales!

With BatchNorm:
Student 1: 95% • Student 2: 95%
Same scale. Easy to compare.

In PyTorch

Conv → BatchNorm2d(128) → ReLU

Knowledge Check

Conv2d uses only 144 parameters while Linear uses 401K. So why doesn't Conv2d lose important information?

Click to reveal

Because the same filter detects the same pattern everywhere in the image. A vertical edge looks the same whether it's in the top-left or bottom-right. Weight sharing means you don't need separate weights for each position — just 9 weights that slide across all positions.

If ConvTranspose2d just "reverses" Conv2d, why can't we literally invert the operation to get back the original image?

Click to reveal

Conv2d is a many-to-one mapping — many different inputs can produce the same output. You can't uniquely reverse it. ConvTranspose2d doesn't truly invert; it learns how to plausibly expand small features into larger ones. It's a learned upsampling, not a mathematical inverse.

BatchNorm normalizes to mean=0, std=1, then has learnable gamma/beta that can undo this. What's the point?

Click to reveal

The network chooses its own scale and shift rather than being stuck with whatever wild range the previous layer produced. Starting from a stable baseline (0,1) and adjusting is much easier than starting from an unpredictable range. It's building on a level foundation vs. a tilted one.
