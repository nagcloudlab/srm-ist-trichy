Lesson 06

When GANs Break

DCGAN produces sharp images — but training is fragile. How to keep it stable.

Why Are GANs Hard to Train?

Normal Neural Network

1 network minimizing 1 loss.
Simple optimization. Goes downhill.

GAN

2 networks with opposite goals.
D wants D(fake)=0. G wants D(fake)=1.
They are fighting each other.

Problem 2: D Wins Too Easily

What Happens

D outputs ≈0 for ALL fakes with near-100% confidence.
G's feedback becomes useless (zero under the minimax loss).
G stops improving.

D says: "fake = 0.0000"
G gradient → uninformative
G is stuck

Why D Wins Easily

D's job is easier than G's job:
D just classifies (real vs fake) — straightforward.
G must create entire images from noise — much harder.

The Vanishing Gradient Problem

D(G(z)) = σ(a)  ·  a = fake logit

When D(G(z)) = 0.0001  (a ≈ −9.2)

minimax: log(1−D(G(z)))
 ∂/∂a = −σ(a) ≈ −0.0001 → saturates
non-saturating: −log D(G(z)) = 9.21
 ∂/∂a = σ(a)−1 ≈ −1 → still strong

We train the non-saturating loss (Goodfellow 2014). The real problem with a near-perfect D: the push is strong but poorly directed — with non-overlapping real/fake distributions, JS divergence is constant (log 2).

Fix 1: One-Sided Label Smoothing

Without Smoothing

real = 1.0, fake = 0.0

D is pushed toward 100% confidence → over-confident, poor teacher

With Smoothing

real = 0.9, fake = 0.0 (Salimans et al. 2016)

D is discouraged from over-confidence on reals → more useful feedback. Smooth only the real side.

The Code Change

# Before:
real_labels = ones(batch, 1)
fake_labels = zeros(batch, 1)

# After:
real_labels = ones(batch, 1) * 0.9
fake_labels = zeros(batch, 1)  # unchanged

Fix 2: Instance Noise

The Idea

Without noise: D sees clear image → easily spots fake

With noise: D sees noisy image → harder to tell real from fake

Like wearing foggy glasses

The Code

real + 0.05 * randn_like(real)

Noise LevelEffect
0.01Almost no effect
0.05Good starting point
0.1Noticeable blur, helps a lot
0.5Too much — D can't learn at all

Some people decay the noise over training — start with 0.1, reduce to 0 gradually.

Fix 3: Learning Rate Balance

Balanced

lr_g = 0.0002, lr_d = 0.0002

→ Stable training

D Too Fast

lr_g = 0.0002, lr_d = 0.002

→ D dominates, G stuck

G Too Fast

lr_g = 0.002, lr_d = 0.0002

→ G cheats, bad quality

First Thing to Try

If training is unstable, lower D's learning rate:

dis_opt = Adam(dis.parameters(),
  lr=0.0001)  # half of G's

A quick heuristic when D dominates. Note: TTUR (Heusel et al. 2017) also uses two learning rates — but there D’s is often larger (e.g. D 4e-4, G 1e-4). Tune the ratio; there is no fixed rule.

GAN Training Checklist

Data

  • Normalize images to [-1, 1]
  • Shuffle dataset

Architecture

  • G output: Tanh (matches [-1, 1])
  • G hidden: ReLU
  • D hidden: LeakyReLU(0.2)
  • D output: Sigmoid
  • BatchNorm in both (NOT D's first)
  • Mirror architecture

Training

  • Adam: lr=0.0002, betas=(0.5, 0.999)
  • One-sided label smoothing: real=0.9, fake=0
  • Same number of D and G steps (1:1)
  • .detach() when training D
  • Weight init: Normal(0, 0.02)

Monitoring

  • Track D_loss and G_loss
  • Track D(real) and D(fake) scores
  • Save images every N epochs
  • Check variety (not all same)

Knowledge Check

Mode collapse means G has low loss and fools D consistently. So why is that a failure?

Click to reveal

Because G found a shortcut, not a solution. It learned to produce one convincing output instead of learning the full distribution. A GAN that only generates "7" has low loss but is useless. The goal is not just to fool D, but to generate diverse, realistic outputs covering all modes of the data.

D has very high loss, G has very low loss. Is that healthy training?

Click to reveal

No! This means G dominates — D cannot tell real from fake. This might sound good, but it means D is giving G no useful feedback. G could be producing garbage that D accepts. Healthy training has both losses hovering around 0.6–1.5, with neither dominating.

Label smoothing trains D toward 0.9 (not 1.0) on reals. Doesn't that make D a worse classifier? Why is worse better?

Click to reveal

A "perfect", over-confident D is actually harmful: its feedback to G is poorly directed (and under the minimax loss it vanishes). Discouraging over-confidence on reals keeps D's signal informative, so G keeps receiving useful learning signals. Smooth only the real labels — the fakes stay at 0. A slightly worse D is a better teacher — the best teacher doesn't just say "you're wrong" with 100% certainty, but gives nuanced feedback that helps the student improve.
