A tensor is an array with superpowers

  • 01
    Same mental model as a list or NumPy array

    A tensor stores numbers in an ordered shape: scalar, vector, matrix, or batch.

  • 02
    The shape tells PyTorch how values are organised

    torch.tensor([1.0, 2.0, 3.0]) → shape [3]

  • 03
    Carries learning information

    A tensor can remember the operations that produced it — enabling automatic differentiation.

The operations already feel familiar

Tensor a [1, 2, 3]
Tensor b [4, 5, 6]
Add a + b = [5, 7, 9]
Element multiply a × b = [4, 10, 18]
Dot product 1×4 + 2×5 + 3×6 = 32

They remember work and can run it at scale

  • 01
    Automatic differentiation

    Track the calculation graph and derive gradients backward through any chain of operations.

  • 02
    Hardware acceleration

    Move the same tensor operations to a GPU with one line — no code rewrite needed.

  • 03
    Neural-network ecosystem

    Use tested layers, losses, optimisers, datasets, and utilities from torch.nn.

Tell PyTorch which value should learn

Learnable value w = tensor(1.0)
requires_grad = True
Fixed values x = 2  •  target = 4
No gradient storage needed

requires_grad=True tells PyTorch to track how the loss depends on w.

The prediction and loss are still ordinary arithmetic

Prediction w × x 1 × 2 = 2
→
Error prediction − target 2 − 4 = −2
→
Loss error² (−2)² = 4

PyTorch silently records every operation. No special syntax needed in the forward pass.

One call calculates the gradient

loss.backward()
gradient of w = −8
Same result as hand calculation: 2 × error × input = 2 × (−2) × 2

PyTorch traces the graph backward and fills w.grad automatically.

Same chain rule · less bookkeeping

Traverses the same chain and fills every parameter's gradient automatically.

nn.Sequential describes the network in order

  • 01
    Sequential means “run in this order”

    Each block receives the output of the block before it.

  • 02
    Linear layers own weights and biases

    PyTorch creates and initialises those parameters — no manual tensors needed.

  • 03
    Activation layers shape behaviour

    ReLU builds non-linear features; Sigmoid maps the final score to a probability.

One input · four hidden neurons · one output

+

Model · loss · optimizer each own one job

01
model

Linear → ReLU → Linear → Sigmoid — produces a probability from every input.

02
BCELoss

Measures the binary classification error between p and the target label.

03
SGD · lr 0.1

Uses the gradients already computed by backward() to update every parameter.

Three actions repeat on every epoch

1 optimizer.zero_grad() — clear old gradients
2 loss.backward() — calculate all gradients
3 optimizer.step() — update every parameter
Clear

Remove gradients left from the previous epoch so they do not accumulate.

Calculate

Backpropagate the loss through every layer to fill each parameter's .grad.

Update

Apply w ← w − lr × gradient for every learned weight and bias.

Add blocks · PyTorch keeps every gradient straight

Shallow network
1 → 4 → 1

Linear • ReLU • Linear • Sigmoid

VS
Deep network
1 → 8 → 8 → 4 → 1

Three hidden Linear + ReLU pairs • one output

Same three-line training loop works for both. PyTorch handles all the extra gradient chains.

Shallow: 13 · deep: 129

Shallow
8 + 5 = 13

1→4 layer plus 4→1 layer.

Deep
1→8: 16   8→8: 72 8→4: 36   4→1: 5
total = 129

More layers add parameters; autograd handles all 129 gradients the same way it handles 13.

PyTorch names the ideas you already know

Idea learned by hand PyTorch block
y = w × x + b nn.Linear
ReLU(z) = max(0, z) nn.ReLU
Sigmoid(z) nn.Sigmoid
Binary cross-entropy nn.BCELoss
Manual chain-rule gradients loss.backward()
w ← w − lr × gradient optimizer.step()

Understanding stays with you

  • 01
    PyTorch does not replace the concepts

    Linear, ReLU, Sigmoid, BCE, and gradient descent behave exactly as you calculated them.

  • 02
    It replaces repetitive bookkeeping

    The calculation graph tracks dependencies and gradient flow so you do not have to.

  • 03
    Your understanding helps you debug

    You can spot wrong shapes, blocked gradients, unsuitable losses, and unstable updates because you know what each piece does.
