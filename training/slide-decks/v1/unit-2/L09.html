Lesson 09

WGAN-GP: Gradient Penalty

Same Lipschitz goal, much smarter enforcement — Gulrajani et al., 2017

1

The Problem with Weight Clipping

The Problem We Need to Fix

Weight Clipping (L08)

Clip every weight to [-0.01, +0.01]

Result: weights cluster at the boundaries

Gradient Penalty (This Lesson)

Let weights be anything — just penalize if gradients get too steep

Result: weights spread naturally, full capacity

Three Problems with Weight Clipping

1. Capacity Loss

Weights cluster at -c and +c. Critic becomes too simple.

Like a chef who can only use salt and pepper — no nuance

2. Sensitive to c

c = 0.001 → gradients vanish
c = 0.1 → gradients explode

Goldilocks problem with no good answer

3. Slow Convergence

Restricted Critic needs many more epochs to learn

Training takes longer for worse results

We want: ||gradient of C|| ≤ 1   —   What if we enforce that directly?

What We Actually Want: 1-Lipschitz

|C(x1) - C(x2)| ≤ |x1 - x2|

In calculus terms:

||∇C|| ≤ 1    everywhere

The gradient's magnitude (norm) should never exceed 1.

Gentle hill = good. Cliff = bad.

2

The Solution: Gradient Penalty

The Gradient Penalty Idea

Old: WGAN (weight clipping)

Loss_C = -C(real).mean() + C(fake).mean()

Then: clip all weights to [-c, c]

New: WGAN-GP

Loss_C = -C(real).mean() + C(fake).mean() + λ × GP

No clipping needed!

The GP Formula

GP = E[( ||∇x̂C(x̂)||2 - 1 )2]
  • Pick a point x̂ (between real and fake)
  • Compute the gradient of C at that point
  • Measure gradient length (L2 norm)
  • If length ≠ 1, penalize by (length - 1)2

Lambda: The Penalty Weight

Loss_C = C(fake).mean() − C(real).mean() + 10 × GP

λ = 0

No constraint: critic scores blow up (L08 lab).

λ = 10

Paper default — used for every experiment.

λ = 1000

Too strong. Critic focuses on penalty, ignores real vs fake.

Rarely tuned in practice — start at 10.

Where Do We Measure the Gradient?

The Interpolation Trick

x̂ = ε × xreal + (1 - ε) × xfake

ε ~ Uniform(0, 1) — random for each image

  • ε = 0 → x̂ = xfake
  • ε = 0.5 → halfway between
  • ε = 1 → x̂ = xreal

Paper (Prop. 1): the optimal critic has slope exactly 1 on lines joining real and fake → penalize (‖∇‖ − 1)², not just ‖∇‖ > 1.

The WGAN-GP critic loss · term by term

LC = E[ C(x̃) ] − E[ C(x) ] + λ · E[ ( ‖∇x̂ C(x̂)‖2 − 1 )2 ]
Read it: fake score minus real score, plus λ times the average squared distance of the critic’s slope from 1

Gradient penalty on a batch of four · worked example

GIVEN
  • ε = 0.25
  • x = (0.8, 0.2)  ·  x̃ = (−0.4, 0.6)
  • ‖∇C‖ at 4 points: 2.0, 1.0, 0.5, 1.5
  • E[C(x̃)] = −1.0  ·  E[C(x)] = 2.0
  • λ = 10
  1. 1x̂ = 0.25·(0.8, 0.2) + 0.75·(−0.4, 0.6) = (−0.1, 0.5)one interpolate (a 2-pixel image)
  2. 2∇C(x̂) = (1.2, 1.6) → ‖∇C‖ = √(1.44 + 2.56) = 2.0its slope
  3. 3(2 − 1)², (1 − 1)², (0.5 − 1)², (1.5 − 1)² = 1, 0, 0.25, 0.25one penalty per sample
  4. 4GP = mean = 0.375 → λ·GP = 3.75average, then weight
  5. 5LC = −1.0 − 2.0 + 3.75 = 0.75Wasserstein part + penalty
  6. =LC = 0.75 — the slope-2 sample alone adds 2.5
Slopes of 0.5 and 1.5 cost the same: the penalty is two-sided.

Gradient Penalty in Code

Step 1: Interpolate

epsilon = torch.rand(bs, 1, 1, 1, device=real.device)
x_hat = epsilon * real + (1-epsilon) * fake
x_hat.requires_grad_(True)

Step 2: Get Critic Scores

scores = critic(x_hat)
# shape: (batch_size, 1)

Step 3: Compute Gradients

grads = torch.autograd.grad(
    outputs=scores,
    inputs=x_hat,
    grad_outputs=ones_like(scores),
    create_graph=True,
    retain_graph=True
)[0]

Step 4: Penalty

grads = grads.view(bs, -1)
norm = grads.norm(2, dim=1)
penalty = ((norm - 1)**2).mean()

What autograd.grad Does

Normal Backprop

loss.backward()

Gradients of loss w.r.t. WEIGHTS

"How should I change weights to reduce loss?"

autograd.grad

torch.autograd.grad(output, input)

Gradient of output w.r.t. INPUT

"How much does the score change when I wiggle a pixel?"

Why create_graph=True?

The GP is part of the loss. When we call loss_C.backward(), PyTorch needs to differentiate through the gradient computation itself (second derivative). Without create_graph=True, PyTorch forgets how it computed the gradient and can't do this.

Why No BatchNorm in the Critic?

BatchNorm

Normalizes across the batch

Each sample's normalization depends on other samples

GP needs independent gradients → broken

Per-Sample Norms

Paper: none, or LayerNorm (recommended)

Our lab: InstanceNorm — also per sample

Each score depends only on its own input → works

Generator still uses BatchNorm

The GP only applies to the Critic. The Generator doesn't need independent gradients per sample, so BatchNorm is fine there.

Why Adam Works Now

WGAN (L08)

Adam with momentum → sometimes unstable (WGAN paper)

Fix there: RMSProp, lr 5e-5, no momentum

WGAN-GP + Adam

No clipping to fight with.

Adam, lr = 1e-4, β1 = 0, β2 = 0.9

β1 = 0 → no momentum; β2 keeps per-weight step sizes

Gulrajani et al. 2017, Algorithm 1

The Critic (InstanceNorm)

class Critic(nn.Module):
  def __init__(self):
    super().__init__()
    self.model = nn.Sequential(
      # 1 x 28 x 28
      nn.Conv2d(1, 64, 4, 2, 1),
      nn.LeakyReLU(0.2),

      nn.Conv2d(64, 128, 4, 2, 1),
      nn.InstanceNorm2d(128,
        affine=True),  # NOT BatchNorm!
      nn.LeakyReLU(0.2),

      nn.Flatten(),
      nn.Linear(128 * 7 * 7, 1),
      # No Sigmoid
    )

Key Differences from WGAN

  • InstanceNorm2d replaces BatchNorm2d (paper: LayerNorm)
  • affine=True lets it learn scale/shift
  • Everything else stays the same

The Training Loop

opt_C = Adam(critic.parameters(), lr=1e-4, betas=(0.0, 0.9))
opt_G = Adam(gen.parameters(),    lr=1e-4, betas=(0.0, 0.9))

for epoch in range(epochs):
  for real, _ in data:
    # ── Train Critic (5 times) ──
    for _ in range(n_critic):
      noise = torch.randn(bs, z_dim, device=device)
      fake  = gen(noise).detach()

      gp = gradient_penalty(critic, real, fake, device)
      loss_C = (critic(fake).mean()
                - critic(real).mean()
                + 10 * gp)            # ← GP replaces clipping

      opt_C.zero_grad()
      loss_C.backward()
      opt_C.step()
      # NO WEIGHT CLIPPING!

    # ── Train Generator (1 time) ──
    noise = torch.randn(bs, z_dim, device=device)
    fake  = gen(noise)
    loss_G = -critic(fake).mean()

    opt_G.zero_grad()
    loss_G.backward()
    opt_G.step()

Knowledge Check

You copy Unit 1’s DCGAN discriminator (with BatchNorm) as your WGAN-GP critic. It trains, no errors. What is wrong?

Click to reveal

Each score now depends on the whole batch, so “gradient of my score w.r.t. my input” is not what the penalty assumes — the constraint is silently invalid. Use no norm, LayerNorm (paper) or InstanceNorm.

Lipschitz only needs ‖∇C‖ ≤ 1. Why penalize (‖∇C‖ − 1)² and push small gradients up?

Click to reveal

The optimal critic has gradient norm exactly 1 on lines joining real and fake (Prop. 1). Aiming at 1 there costs nothing and gives a simple, smooth target; empirically it doesn’t over-constrain the critic.

GP only checks points between real and fake. What if C is a cliff somewhere else?

Click to reveal

Then C is not truly 1-Lipschitz — GP is a soft, sampled constraint. It works because G’s gradient only ever comes from C at the fakes, and that region (and the path to the reals) is exactly what we sample.
