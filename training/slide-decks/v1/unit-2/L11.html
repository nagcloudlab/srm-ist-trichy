The Big Idea: Latent Space Has Structure

Every noise vector z maps to a different image:

z = [0.3, -1.2, 0.7, ...] → thin, straight 7
z = [1.1, 0.5, -0.3, ...] → thick, tilted 3
z = [-0.8, 2.1, 0.1, ...] → round, small 0

The Surprising Discovery

A well-trained GAN doesn't scatter images randomly. It organizes them. Similar images end up near each other.

Controllable Directions

Moving in the latent space changes specific features:

↑ Direction A

Makes digits thicker

→ Direction B

Makes digits more tilted

↗ Direction C

Makes digits taller

Key Insight

The GAN discovers these directions on its own during training. We just need to find them.

Latent Space Interpolation

Walk between two noise vectors:

z_interp = (1 - α) × z1 + α × z2
α: 0.0 → Image A  ·  0.5 → blend  ·  1.0 → Image B

Lerp vs Slerp (Gaussian z)

  • Typical ‖z‖ ≈ √64 = 8; lerp midpoint ≈ √32 = 5.7
  • Slerp follows the arc → norm stays typical (White, 2016)

Quality Signal

Sharp in-between = smooth latent space
Blurry in-between (even with slerp) = holes

Interpolation in Code

z1 = torch.randn(1, z_dim)    # noise for image A
z2 = torch.randn(1, z_dim)    # noise for image B

steps = 8
for i in range(steps):
    alpha = i / (steps - 1)       # 0.0 to 1.0
    z_interp = (1 - alpha) * z1 + alpha * z2
    image = gen(z_interp, label)

What You'll See

Image A → gradual blend → gradual blend → Image B
Every frame looks like a real digit — no blurry garbage in between.

Why lerp midpoints fall off the shell · worked example

GIVEN
  • d = 64
  • z₁, z₂ ∼ N(0, I), independent
  • t = 0.5
  1. 1‖z₁‖ ≈ ‖z₂‖ ≈ √64 = 8simulated mean 7.97
  2. 2z₁·z₂ ≈ 0 → Ω ≈ 90°simulated 90.0° ± 7.2°
  3. 3lerp: ‖½z₁ + ½z₂‖ ≈ ½ √(8² + 8²) = 5.66simulated 5.63
  4. 4slerp weights: sin 45° / sin 90° = 0.707 eachlarger than ½
  5. 5slerp: 0.707 · √(8² + 8²) = 8.0simulated 7.98

Simulated over 100,000 random pairs · the lerp midpoint is ≈ 0.71 of the typical length for any z_dim.

Latent Space Arithmetic

The word2vec analogy:

King - Man + Woman = Queen

GANs can do the same with images:

Thick 7 - Thin 7 + Thin 3 = Thick 3

Why It Works

Subtracting two z vectors that differ in one feature isolates that feature's direction. Add it to any z = apply the feature.

DCGAN (Radford et al. 2015): smiling woman − neutral woman + neutral man = smiling man — using the average z of 3 samples per concept.

Arithmetic in Code

# Find the "thickness" direction
thickness_dir = z_thick - z_thin

# Apply to a new digit
z_new = torch.randn(1, z_dim)
z_thicker = z_new + 0.5 * thickness_dir
z_thinner = z_new - 0.5 * thickness_dir

img_normal  = gen(z_new, label)
img_thicker = gen(z_thicker, label)
img_thinner = gen(z_thinner, label)

The 0.5 controls how much to apply. Bigger = more effect. Too big = unrealistic images.

Next: How do we actually find those feature directions? Three methods coming up.

Finding Directions: Averaged Method

  • Step 1: Generate LOTS of images
  • Step 2: Sort them by feature (thick vs thin)
  • Step 3: Average z vectors in each group
  • Step 4: Difference of averages = direction
z_thick_avg = mean(all z that made thick digits)
z_thin_avg  = mean(all z that made thin digits)
direction   = z_thick_avg - z_thin_avg

Single Pair (Noisy)

z_thick_7 - z_thin_7 captures "thick" but also stroke style, specific quirks, random noise.

Averaged (Clean)

Individual quirks cancel out. What remains is only the thickness direction. Like opinion polls — one person is noisy, 1000 opinions reveal the trend.

Latent arithmetic · term by term

znew = z̄thick 7 − z̄thin 7 + z̄thin 3
Read it: start from a thin 3, then add the step that turns thin into thick

cGAN Advantage

With a Conditional GAN, you can find directions within a single class. Generate 500 different 7s, sort by thickness, find the thickness direction that works specifically for 7s.

Single-Dimension Exploration

Vary one z dimension at a time:

z_base = torch.randn(1, z_dim)

for dim in range(z_dim):
  for value in [-3, -2, -1, 0, 1, 2, 3]:
    z_mod = z_base.clone()
    z_mod[0, dim] = value
    img = gen(z_mod, label)
DimensionWhat Changes
Dim 0thin → medium → thick
Dim 1straight → … → tilted
Dim 2short → … → tall
Dim 3??? (something subtle)

Illustrative — in a plain GAN most dims are entangled (one dim changes several features). Directions usually beat single dims.

Conditional Interpolation

Keep noise fixed, blend label embeddings:

embed_3 = gen.label_embed(tensor([3]))
embed_7 = gen.label_embed(tensor([7]))

z_fixed = torch.randn(1, z_dim)

for alpha in [0.0, 0.2, 0.4, ...]:
  embed_mix = (1-alpha)*embed_3
            + alpha*embed_7
  x = cat([z_fixed, embed_mix], dim=1)
  img = gen.model(x)

Noise Truncation

Limit z to a smaller range:

# Truncated normal: resample |z_i| > t
z = torch.randn(n, z_dim)
bad = z.abs() > t
while bad.any():
  z[bad] = torch.randn(int(bad.sum()))
  bad = z.abs() > t

Used In

  • BigGAN (2018): truncated normal z, threshold t
  • StyleGAN: w′ = w̄ + ψ(w − w̄) in W space
  • Clamp ≠ truncate: t = 1 clamps ~32% of entries to ±1

Truncation trades variety for typical samples · worked example

zi ∼ N(0, 1),   resample while |zi| > t
GIVEN
  • zi ∼ N(0, 1)
  • resample while |zi| > t
  1. 1t = 2 → 4.6% of entries resampled · std 0.88almost no change
  2. 2t = 1 → 31.7% resampled · std 0.54samples hug the mean
  3. 3t = 0.5 → 61.7% resampled · std 0.28very typical, little variety
  4. 4smaller std → G sees only typical zquality ↑ · diversity ↓
  5. =lower t: cleaner images, less variety (BigGAN’s truncation trick)
Clamping is different: at t = 1 it pins ~32% of entries exactly to ±1.

Knowledge Check

Endpoints look great, but the middle of your lerp walk looks washed out. Is the GAN broken?

Click to reveal

Not necessarily. With z_dim = 64 every training z has norm ≈ 8; the lerp midpoint has ≈ 5.7 — an input G never saw. Try slerp first; only if that is blurry too does the latent space have holes.

A common shortcut “truncates” with z.clamp(-1, 1). How many entries change, and why is that not BigGAN’s trick?

Click to reveal

P(|zi| > 1) ≈ 32% — about 20 of 64 entries become exactly ±1, a spike of mass on the box edges. BigGAN resamples those entries, so z stays a smooth (truncated) Gaussian.

Blend label embeddings 3 → 7, or blend the one-hot vectors and then embed. Which gives smoother morphs?

Click to reveal

Identical. nn.Embedding is a linear map: embed(y) = one_hot(y) · W, so mixing one-hots then multiplying by W equals mixing embeddings. Either way G gets an input it never trained on — smoothness depends on G, not on the blend.
