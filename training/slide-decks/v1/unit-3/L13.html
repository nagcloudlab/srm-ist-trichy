Grabbing Features with a Hook

class InceptionFeatureExtractor: def __init__(self, device): self.model = inception_v3( weights=Inception_V3_Weights.DEFAULT ) self.model.eval().to(device) self.model.avgpool .register_forward_hook( self._hook ) def _hook(self, mod, inp, out): self.features = out.flatten(1) @torch.no_grad() def extract(self, images): self.model(images) return self.features.cpu()

What's a hook?

A function PyTorch calls automatically when a specific layer runs.

"When avgpool runs during forward(), also call _hook()"

_hook grabs the output and saves it. We run the full model but only keep the pool3 features.

Result

Each image in → one 2048-dim vector out

Preprocessing for Inception

Inception Expects

3 channels (RGB)

299 x 299 pixels

ImageNet normalization

mean=[0.485, 0.456, 0.406]
std=[0.229, 0.224, 0.225]

For MNIST (1x28x28)

  1. Scale from [-1,1] to [0,1]
  2. Repeat grayscale → 3 channels
  3. Resize 28 → 299 (bilinear)
  4. Apply ImageNet normalization

Critical Rule

Same preprocessing for real AND fake. Different resizing can shift FID by several points!

Computing Statistics

def compute_statistics(features): # features: (N, 2048) mu = np.mean(features, axis=0) sigma = np.cov(features, rowvar=False) return mu, sigma # mu: (2048,) vector # sigma: (2048 x 2048) matrix

Mean (mu)

The "average image" in feature space. If fakes have different average features than reals → centers are far apart.

Covariance (Sigma)

How features vary together. "When eye-feature is high, is face-feature also high?" Captures the shape and spread of the distribution.

The FID Formula in Code

FID = ||mu_r - mu_f||^2 + Tr(Sigma_r + Sigma_f - 2 * sqrtm(Sigma_r @ Sigma_f))
from scipy.linalg import sqrtm def calculate_fid(mu_r, sig_r, mu_f, sig_f): # Term 1: center distance diff = mu_r - mu_f mean_term = np.dot(diff, diff) # Term 2: shape distance covmean = sqrtm(sig_r @ sig_f) if np.iscomplexobj(covmean): covmean = covmean.real trace_term = np.trace( sig_r + sig_f - 2 * covmean ) return mean_term + trace_term

sqrtm = matrix square root

For a number: sqrt(9) = 3 because 3 x 3 = 9

For a matrix: sqrtm(A) = B where B x B = A

Covariance is a matrix, not a number. We can't just use sqrt().

Why iscomplexobj?

Numerical precision can produce tiny imaginary parts. We discard them.

FID by hand in 1-D: 1.25 · worked example

GIVEN
  • real: μr = 0, σr = 1
  • fake: μg = 0.5, σg = 2
  1. 1‖μr − μg‖² = (0 − 0.5)² = 0.25centre distance
  2. 2Σ = σ²: Σr = 1, Σg = 41-D covariance = variance
  3. 3(ΣrΣg)½ = √4 = 2matrix sqrt = ordinary sqrt
  4. 4Tr(1 + 4 − 2·2) = 1shape distance = (σr − σg)²
  5. 5in 1-D: FID = (μr − μg)² + (σr − σg)²both terms are squared gaps
  6. =FID = 0.25 + 1 = 1.25
Fake too spread out (σ 2 vs 1) costs 1.0 — more than the shifted centre (0.25). FID punishes wrong variety.

Putting It All Together

def compute_fid(real_images, fake_images, extractor, batch_size=64): # 1. Extract features for real images (in batches) real_feats = [] for i in range(0, len(real_images), batch_size): batch = preprocess_for_inception(real_images[i:i+batch_size]) real_feats.append(extractor.extract(batch)) real_feats = torch.cat(real_feats).numpy() # 2. Same for fake images fake_feats = [] for i in range(0, len(fake_images), batch_size): batch = preprocess_for_inception(fake_images[i:i+batch_size]) fake_feats.append(extractor.extract(batch)) fake_feats = torch.cat(fake_feats).numpy() # 3. Compute statistics mu_r, sig_r = compute_statistics(real_feats) mu_f, sig_f = compute_statistics(fake_feats) # 4. Calculate FID return calculate_fid(mu_r, sig_r, mu_f, sig_f)

Usage: fid = compute_fid(real_imgs, fake_imgs, extractor)

Common Pitfalls

Sample Count

same distribution, 64-d sim:
N = 100: FID ≈ 21
N = 500: FID ≈ 4.4
N = 2,000: FID ≈ 1.1
N = 10,000: FID ≈ 0.22

Small N biases FID upward. Report N; compare only at the same N.

Preprocessing Mismatch

Real: bilinear resize
Fake: nearest-neighbor

Different preprocessing = wrong FID! Same method for both, always.

FID ≈ 0 Trap

Could mean:

  • Perfect generation (unlikely)
  • Memorization! (likely)
  • Computed real vs real by mistake

Knowledge Check

You compute FID = 0 for your GAN. Your colleague says "Perfect GAN!" Should you celebrate?

Click to reveal

No! FID ≈ 0 likely means memorization — your Generator just copied the training data. Check by finding the nearest neighbor of each generated image in the training set. If they're pixel-identical, your GAN memorized instead of learning. Also check if you accidentally computed real vs real.

Why do we use pool3 features instead of the final class probabilities? What would go wrong?

Click to reveal

The final layer outputs 1000 ImageNet class probabilities. For MNIST digits or faces, none of those classes are relevant — you'd get meaningless probability distributions. Pool3 features capture general visual patterns (edges, shapes, textures) that are useful for ANY image domain, not just ImageNet classes.

If Inception was trained on ImageNet (photos of objects), why does it work for evaluating MNIST (handwritten digits)?

Click to reveal

Deep networks learn hierarchical features. Early layers learn edges and textures, middle layers learn shapes and patterns, pool3 captures high-level structural features. These features generalize across domains — "sharp edges vs blurry blobs" matters for digits AND photos. It's not perfect for MNIST, but it's remarkably effective.
