Paired vs Unpaired Translation

Paired Translation

Every input has an exact matching output.

  • Edge drawing of shoe #1 ↔ Photo of shoe #1
  • Edge drawing of shoe #2 ↔ Photo of shoe #2
  • Same scene, two representations

Hard to collect, easier to train

Solved by Pix2Pix (L17)

Unpaired Translation

Two separate collections, no matching pairs.

  • 100 horse photos (various)
  • 100 zebra photos (different zebras)
  • No horse matches any specific zebra

Easy to collect, harder to train

Solved by CycleGAN (L19)

The Encoder-Decoder Architecture

Encoder-Decoder: Compress & Expand

Encoder (like a Discriminator)

Conv + stride 2 → shrink spatial size
256 → 128 → 64 → ... → 1x1x512

Decoder (like a Generator)

ConvTranspose2d + stride 2 → expand back
1x1x512 → ... → 64 → 128 → 256x256x3

The Bottleneck Problem

Everything must squeeze through 512 numbers

Input: a street scene with 50 buildings, 12 cars, 200 windows

Bottleneck: 512 numbers — computed from the input, not a random z like the 64/100-d noise of Units 1–2

The encoder KNOWS where everything is at the early layers. But by the bottleneck, those precise positions are compressed away.

Result: Blurry Output

The decoder knows the general layout but lost all fine details:

  • Where every building edge is
  • The exact color of every pixel
  • The position of every window

The fix? Skip connections (L17)

Why Use a GAN for This?

L1/L2 Loss Alone

"Minimize average pixel difference"

When several colours are plausible: L2 picks the mean, L1 the median.

Red or blue car → a compromise colour that is neither

Result: blurry, washed out

GAN Loss Added

"Be indistinguishable from real"

The Discriminator catches blurry outputs. Forces G to commit to one answer.

Pick red OR blue — not the average!

Result: sharp and realistic

L1 only
Blurry but correct

The Discriminator's New Job

Regular GAN Discriminator

"Is this image real or fake?"

Input: one image

Output: real / fake

Image-to-Image Discriminator

"Does this OUTPUT match this INPUT?"

Input: input + output concatenated (6 channels)

Output: real / fake

PatchGAN: A Smarter Discriminator

Regular D: One Score

256x256 image → one number (0.73)

"Overall 73% real" — but WHERE is it fake?

PatchGAN: Grid of Scores

256x256 image → 30x30 grid

Each cell = "Is this local patch real or fake?"

The Full Image-to-Image Framework

Why λ = 100?

λ = 0 (no L1)

Sharp but wrong images.

"Here's a beautiful shoe that doesn't match your edges"

λ = 100 (Pix2Pix)

Sharp AND correct images.

GAN keeps it sharp, L1 keeps it faithful

λ = 10000 (too much L1)

Blurry but correct images.

"Here's the right shoe but it looks like watercolor"

The 100:1 ratio was found empirically by the Pix2Pix authors. It works across many tasks.

Knowledge Check

If we already have paired data and L1 loss, why do we even need a GAN?

Click to reveal

L1 alone picks the median of the plausible answers (L2 the mean) — a blurry compromise. The GAN loss makes G commit to one sharp answer, because D catches blurry, averaged textures. L1 still matters: it keeps the low frequencies correct.

Why does D need to see the INPUT image too, not just the output?

Click to reveal

If D only judges "is this a realistic shoe?", the Generator can produce ANY realistic shoe regardless of the input edges. By showing D both input and output, D checks whether the output matches the input. G is forced to produce edges-consistent output.

PatchGAN outputs 30x30 = 900 scores. How is that better than one score?

Click to reveal

Each score focuses on a local 70x70 region. An image might have realistic buildings but blurry windows — one global score would average these, but PatchGAN catches the blurry region specifically. It acts like a local texture critic everywhere.
