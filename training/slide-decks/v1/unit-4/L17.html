Lesson 17

Pix2Pix: U-Net + PatchGAN

Skip connections save the details — the first general-purpose paired translator

The Bottleneck Tragedy

The encoder KNOWS where everything is

At early layers (128x128, 64x64), the encoder has precise edge positions, window locations, every detail.

But by the bottleneck (1x1x512), all those precise positions are compressed away.

The decoder has to GUESS

"There's a building somewhere... maybe on the left?"

Result: blurry edges, wrong positions, lost details.

“What if we let the decoder directly access the encoder's feature maps?”

That's the U-Net idea.

U-Net: Skip Connections to the Rescue

Why It's Called U-Net

The U shape

Encoder goes down (compress).
Decoder goes up (expand).
Skip connections bridge across.

Originally invented for medical image segmentation (Ronneberger et al., 2015). Perfect for image-to-image translation.

What "concat" means

At the 64×64 level:

  • Decoder up-conv produces: 64x64x128
  • Encoder skip had: 64x64x128
  • Concatenate: 64x64x256
  • Next up-conv: 128x128x64

Double the channels at each skip!

decoder_input = concat(upsampled_below, encoder_skip) → doubled channels → conv back

U-Net: The Core Pattern in Code

Encode: save each layer

e1 = enc1(x)    # save!
e2 = enc2(e1)  # save!
e3 = enc3(e2)  # save!
...
b = bottleneck(e7)

Decode: concat with saved

d1 = dec1(b)
d1 = cat([d1, e7])  # skip!
d2 = dec2(d1)
d2 = cat([d2, e6])  # skip!
...
output = final(d7)

Without skip: decoder ONLY knows what survived the bottleneck

With skip: decoder knows the big picture AND the exact positions

Why "70x70"?

Each cell in the 30x30 output has a receptive field of 70x70 pixels in the original 256x256 input.

The Pix2Pix paper tested patch sizes:

  • 1x1 (PixelGAN): sharp colors, no structure
  • 16x16: some texture
  • 70x70: good textures + structure
  • 256x256 (full): no better, more params

The Pix2Pix Loss

Generator Loss

fake = G(input)
d_fake = D(cat(input, fake))

loss_GAN = BCE(d_fake, ones)
loss_L1 = L1(fake, target)

loss_G = loss_GAN + 100 * loss_L1

Discriminator Loss

real_pair = cat(input, target)
fake_pair = cat(input, fake.detach())

loss_real = BCE(D(real_pair), ones)
loss_fake = BCE(D(fake_pair), zeros)

loss_D = (loss_real + loss_fake) / 2

BCEWithLogitsLoss: sigmoid + BCE in one step — numerically stable, handles PatchGAN grids automatically

Dropout as Noise

The Problem

U-Net is SO powerful that it can learn to just copy the input through skip connections and ignore the bottleneck entirely.

Result: output = slightly modified input (no real translation)

The Fix: Dropout(0.5)

  • Randomly drops 50% of activations
  • Forces the network to use multiple paths
  • Kept ON at test time (unusual!)
  • Adds controlled randomness to output

Models uncertainty: colorization has multiple valid answers

Data Augmentation: The Critical Rule

WRONG: Different transforms

input_aug = RandomCrop(input)
target_aug = RandomCrop(target)
# Different crops! Misaligned!

RIGHT: Same transform for both

both = cat([input, target])
both = RandomCrop(both)
input_aug, target_aug = split(both)
# Perfectly aligned!

Pix2Pix Augmentation Recipe

1. Resize to 286x286 → 2. Random crop to 256x256 → 3. Random horizontal flip (50%)
All applied identically to input AND target.

Why Pix2Pix Works So Well

1

L1 Loss

"Stay close to the ground truth"

Handles overall structure and color. Prevents hallucination. Alone: blurry

"Look realistic to D"

Handles sharpness and texture. Forces realistic details. Alone: ignores input

"Don't lose the details"

Knowledge Check

U-Net gives the decoder direct access to encoder features. Why not just remove the bottleneck entirely?

Click to reveal

The bottleneck forces the network to learn semantic meaning — WHAT objects are, not just WHERE they are. Without it, the decoder would just copy the input through skip connections with minimal transformation. The bottleneck provides the "what to change" signal, while skips provide "where things are."

Pix2Pix trains with batch size 1. How does BatchNorm work with a single image?

Click to reveal

With one image, the “batch” statistics are just that image’s own mean and variance over its pixels — so BatchNorm behaves like InstanceNorm. Pix2Pix uses these per-image statistics at test time too, rather than running averages.

What breaks if you apply different random crops to input and target?

Click to reveal

The input and target become misaligned. The model tries to learn a mapping where the edges in the input don't correspond to the structures in the target. The L1 loss gives nonsensical gradients, and the model either fails to converge or learns to ignore the input entirely.
