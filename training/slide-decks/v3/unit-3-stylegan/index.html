Every generator so far feeds z in at the very start. The network then turns it into the whole image, so every number in z ends up affecting a bit of everything: pose, shape, colour. That is entanglement, the problem from Part B chapter 9. StyleGAN’s big idea is to separate these controls.

A plain stack of eight fully connected layers with LeakyReLU, 512 numbers in and 512 out. Simple, but it changes everything: the generator never sees z directly, only w. In lab-15 the model is smaller: z of 64, w of 128, four layers.

StyleGAN · §2 · Why does this help?

Why not use z directly?

Z-space: a fixed round ball

clothes crammed into a ball

mapping →

W-space: any shape it needs

clothes laid out in drawers

Key idea

z must fill a round Gaussian ball, so features tangle. w is free to spread features apart: less entangled.

Z-space has a fixed shape: we sample z from a round Gaussian, so the data’s features have to be squeezed to fit that ball, which tangles them. W-space has no such rule; the mapping network can stretch and fold space so that separate features end up in separate directions. The lesson’s analogy: clothes crammed into a ball versus laid out in drawers. This is why latent directions work better in W than in Z.

StyleGAN · §2 · In code

The mapping network in PyTorch

class MappingNetwork(nn.Module):
    def __init__(self, z_dim=512, w_dim=512, n=8):
        super().__init__()
        layers = []
        for i in range(n):
            layers += [nn.Linear(z_dim if i == 0 else w_dim, w_dim),
                       nn.LeakyReLU(0.2)]
        self.net = nn.Sequential(*layers)
    def forward(self, z):
        return self.net(z) # z -> w

That is the whole mapping network: Linear plus LeakyReLU, eight times. In lab-15, MappingNetwork uses four layers to keep the model small.

StyleGAN · §9 · Learned constant

The image starts from a learned constant

DCGAN

z, reshaped to 4×4

changes every sample

vs

StyleGAN

4×4×512, the same for every image, learned in training

So

All the variety comes from w (through AdaIN) and from noise, never from the starting tensor.

A radical change from DCGAN. In DCGAN, z is reshaped into the first feature map, so every sample starts differently. In StyleGAN, the first feature map is a learned 4×4×512 tensor: a parameter, identical for every image. Think of a blank canvas with a faint underdrawing that training has shaped. Everything that makes one face different from another comes later, from w and from noise. Lab-15 experiment 5 visualises this constant.

Chapter 5: Step 3: AdaIN, a style dial at every layer.

StyleGAN · §3 · AdaIN

AdaIN = wash, then paint

AdaIN(x, w) =

γ(w)

scale from w

·

(x − mean) / std

per channel, per image

+

β(w)

shift from w

1 · Wash (normalise)

Instance norm strips the old style: every channel becomes mean 0, std 1.

2 · Paint (re-style)

A small linear layer turns w into γ and β: the new scale and shift for every channel.

Name

Adaptive Instance Normalisation: instance norm whose scale and shift come from w.

Two steps. First wash the canvas: instance normalisation, which students met with WGAN-GP in Unit 2, makes every channel of this image mean 0, standard deviation 1, removing whatever style was there. Then paint: a learned linear layer reads w and outputs one scale γ and one shift β per channel, and we apply them. Because each layer has its own linear layer, each layer reads different style information from the same w.

Read it as

Whatever the layer had before, the output’s mean and spread are now set by w.

Work one channel with three numbers. x = 2, 4, 6: mean 4, standard deviation about 1.63 (population). Wash: subtract 4 and divide by 1.63, giving −1.22, 0, 1.22. This layer’s style, read from w, says γ = 2 and β = 0.5. Paint: 2 × −1.22 + 0.5 = −1.95, then 0.5, then 2.95. The new channel has mean β = 0.5 and spread γ × 1.63 ≈ 3.27. The pattern of the values is kept; the overall level and contrast now come from w.

StyleGAN · §3 · In code

AdaIN in PyTorch

class AdaIN(nn.Module):
    def __init__(self, w_dim, channels):
        super().__init__()
        self.style = nn.Linear(w_dim, channels * 2) # w -> gamma, beta
    def forward(self, x, w):
        gamma, beta = self.style(w).chunk(2, dim=1)
        gamma = gamma[:, :, None, None]; beta = beta[:, :, None, None]
        mean = x.mean(dim=[2, 3], keepdim=True)
        std = x.std(dim=[2, 3], keepdim=True) + 1e-8
        return gamma * (x - mean) / std + beta

One linear layer per AdaIN produces 2 × channels numbers: a γ and a β for every channel. Mean and std are taken over the spatial dimensions only, separately for each image and each channel: that is instance normalisation. Lab-15 writes the scale as 1 + γ so that, at initialisation, AdaIN starts close to plain instance norm.

StyleGAN · §4 · Layer hierarchy

Early layers: big things. Late layers: small things.

Coarse

4×4 – 8×8

pose, face shape, glasses

Medium

16×16 – 32×32

eyes, nose, mouth, hair style

Fine

64×64 – 1024×1024

colour, skin and hair texture

Analogy

Sketch, then features, then the fine brush: the same order as the artist.

Because each block works at a different resolution, its AdaIN can only influence things of that size. At 4×4 and 8×8 there are only a few pixels, so the style there sets the big picture: pose, face shape, whether there are glasses. At 16×16 and 32×32 it sets features: eyes, mouth, hair style. From 64×64 upward it sets colour and texture. How do we know? Style mixing, next chapter.

StyleGAN · §5 · Style mixing

A’s shape with B’s colouring

Person A

w_A

+

Person B

w_B

→

Mixed

coarse w_A · fine w_B

coarse layers ← w_A: pose, shape, glasses

fine layers ← w_B: skin and hair colour

Why it works

Each layer gets its own copy of w, so we can hand different layers different w’s.

The proof of the layer hierarchy. Map two noise vectors to w_A and w_B. Feed w_A to the coarse layers and w_B to the fine layers. The result has A’s pose, face shape and glasses with B’s colouring. Impossible in DCGAN, where z enters once. Lab-15 experiment 1 makes a full grid of this on MNIST.

StyleGAN · §5 · Style mixing in code

One w per layer, switched at a crossover

def style_mix(G, mapping, z_A, z_B, crossover=4):
    w_A, w_B = mapping(z_A), mapping(z_B)
    ws = [w_A if i < crossover else w_B # coarse from A, fine from B
          for i in range(G.num_layers)]
    return G.forward_with_styles(ws)

Crossover early

Mostly B: only pose and shape come from A.

Crossover late

Mostly A: only colour and texture come from B.

In training

Mixing regularisation: StyleGAN mixes two w’s in a share of training images, so neighbouring layers can’t rely on each other.

The crossover index picks which layers take w_A and which take w_B. Move it earlier and less of A survives. StyleGAN also uses mixing as a regulariser during training (90% of images in the paper): it switches w at a random layer, which forces each layer’s style to work on its own and keeps the levels separate.

Freeze w and change only the noise: same person, same expression, same colours; only the stray hair strands move. That is the job split. Style says what the face looks like; noise supplies the random placement that real photos have, so the network doesn’t have to fake randomness from w. StyleGAN · §6 · Noise in code

One style block: conv → + noise → AdaIN

class StyleBlock(nn.Module):
    def __init__(self, in_ch, out_ch, w_dim):
        super().__init__()
        self.conv = nn.Conv2d(in_ch, out_ch, 3, padding=1)
        self.adain = AdaIN(w_dim, out_ch)
        self.noise_scale = nn.Parameter(torch.zeros(1, out_ch, 1, 1)) # learned B
    def forward(self, x, w):
        x = self.conv(x)
        noise = torch.randn(x.shape[0], 1, x.shape[2], x.shape[3], device=x.device)
        x = x + self.noise_scale * noise
        return self.adain(x, w)

One block of the synthesis network. A single-channel noise image, fresh for every forward pass, is scaled by a learned per-channel factor B and added after the convolution, then AdaIN applies the style. B starts at zero, so the network learns how much noise each layer should use. Lab-15 experiment 6 plots those learned scales.

Chapter 9: Truncation: quality vs variety.

StyleGAN · §8 · Truncation trick

Pull w toward the average face

w′ = w_mean + ψ · (w − w_mean)

ψ = 1

no change: full variety, some odd faces

ψ = 0.7

the usual choice: good quality and variety

ψ = 0.5

cleaner, but faces look alike

ψ = 0

always the average face

w̄ is the average w over many random z’s, computed once. Truncation moves each w part of the way toward it: with w = 4 and w̄ = 0, ψ = 0.7 gives 2.8, ψ = 0.5 gives 2, ψ = 0 gives the average. Rare w’s far from the average are where the generator saw little data, so pulling them in improves quality but reduces variety. Students met truncation in z in L11 (BigGAN re-samples the tails); StyleGAN does it in W, where the space is smoother, so every style shrinks evenly. Lab-15 experiment 2.

StyleGAN · §8 · Truncation in code

Truncation in four lines

with torch.no_grad():
    w_mean = mapping(torch.randn(10000, 512)).mean(0, keepdim=True) # once
def generate(z, psi=0.7):
    w = mapping(z)
    w = w_mean + psi * (w - w_mean)
    return synthesis(w)

Only at sampling

Truncation is used when generating, not during training.

Compute the average w once from ten thousand random z’s. At sampling time, shrink each w toward it with ψ. Training is unaffected; this is a dial for the demo, not part of the loss.

Chapter 10: Training StyleGAN.

StyleGAN · §7 · Progressive growing (StyleGAN 1)

Grow the image: 4×4 → 8×8 → … → 1024×1024

4²

8²

16²

32²

64²

… 1024²

out = (1 − α) · upsample(old) + α · new_layer    α: 0 → 1

Like learning to draw

Rough shapes first, then details. Each new layer is faded in slowly. StyleGAN 2 later dropped this.

StyleGAN 1 kept progressive growing from ProGAN (Karras et al., 2018): train G and D at 4×4, then add layers for 8×8, and so on up to 1024×1024. Each new layer is faded in: the output blends the upsampled old image with the new layer’s output, with α rising from 0 to 1. The network never has to learn everything at once. StyleGAN 2 replaced this with skip and residual connections.

StyleGAN · §7 · The loss

The loss: tools from Unit 2

StyleGAN on FFHQ

Non-saturating loss (Part A, ch 5) + R1 penalty on real images.

R1 penalty

A gradient penalty, like WGAN-GP, but only at real images: keep D’s slope small there.

Lab-15 (MNIST)

WGAN-GP: the loss you already built in lab-09.

Discriminator

An ordinary conv network: all of StyleGAN’s new ideas are in G.

Nothing new to learn in the loss. On the FFHQ faces dataset, StyleGAN uses the non-saturating generator loss from Part A chapter 5, plus R1 regularisation: a penalty on the squared gradient of D at real images, the same family as the gradient penalty in Part A chapter 12. Lab-15 trains with WGAN-GP for stability. The discriminator is a standard convolutional network.

Chapter 11: After StyleGAN.

StyleGAN · §10 · StyleGAN evolution

Three versions, three fixes

StyleGAN

2019

• Mapping network, AdaIN, noise

• Progressive growing

• Truncation in W

StyleGAN 2

2020

• AdaIN caused “water droplet” blobs → weight demodulation

• No progressive growing

• Path length regularisation: smoother W

StyleGAN 3

2021

• Textures “stuck” to pixel positions

• Alias-free layers

• Objects move naturally in interpolation

StyleGAN 2 found that AdaIN’s normalisation produced blob-like “water droplet” artifacts; it moved the style into the convolution weights instead (modulation and demodulation), dropped progressive growing for skip and residual designs, and added path length regularisation so a small change in w gives a small change in the image. StyleGAN 3 fixed “texture sticking”: details glued to pixel coordinates during interpolation, caused by aliasing.

StyleGAN · §11 · Why it matters

The ideas outlived the faces

Mapping networks

Transform the noise before using it: now standard.

Multi-scale style

Coarse, medium and fine control.

W-space editing

Latent directions from Part B work better in W.

GAN inversion

Find the w of a real photo, then edit it.

Beyond faces

Cars, rooms, cats, art; cartoon versions by fine-tuning.

StyleGAN’s ideas spread far beyond faces. Latent editing in W-space is Part B’s z + α·d, now with cleaner directions. GAN inversion finds the w that reproduces a real photo, so the photo can be edited with those directions. Fine-tuning a face StyleGAN on cartoons gives domain adaptation.
